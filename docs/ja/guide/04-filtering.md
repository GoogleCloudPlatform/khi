# フィルタリング

[< 前へ: タイムラインビュー](./03-timeline-view.md) | [次へ: ログビュー >](./05-log-view.md)

---

KHI のツールバーには、膨大なログデータから目的のタイムラインやログを効率的に抽出するための強力なフィルタリング機能が用意されています。UI 上で直感的に操作できる通常モードと、CEL（Common Expression Language）式を用いて高度な条件を指定できるアドバンスドモードを切り替えて利用できます。

## 画面構成

### 通常モード

初期状態では通常モードのツールバーが表示されています。

![通常モードのツールバー](/docs/ja/images/filter-normal-toolbar.png)

| 番号 | 要素名 | 説明 |
| :--- | :--- | :--- |
| **1** | **アドバンスドモード切り替えボタン** | 通常モードと CEL 式を用いるアドバンスドモードを切り替えます。 |
| **2** | **タイムラインフィルタ追加ボタン** | タイムラインを絞り込むためのフィルタ条件を追加します。 |
| **3** | **最低重大度フィルタ** | 指定した重大度以上のログのみを表示するように絞り込みます。 |
| **4** | **ログ検索入力欄** | ログ本文のキーワード検索やフィルタリングを行います。 |
| **5** | **タイムゾーン設定** | 画面上に表示されるログやタイムラインのタイムゾーンを切り替えます。 |

### アドバンスドモード

ツールバー左端のアイコンをクリックすると、アドバンスドモードに切り替わります。

![アドバンスドモードのツールバー](/docs/ja/images/filter-advanced-toolbar.png)

| 番号 | 要素名 | 説明 |

| **3** | **ネガティブタイムラインフィルタ** | マッチするタイムラインを除外するための CEL 式を入力します。 |

## フィルタリングの基本コンセプト

通常モードのフィルタリングを使用する上で、重要な基本原則は以下の通りです。

> **「KHI はまずタイムラインをフィルタリングし、その抽出されたタイムライン内のログに対してログフィルタリングを行う」**

タイムラインのフィルタリングは、ログ 1 行ごとの評価に比べてはるかに軽量です。そのため、まずタイムラインフィルタで対象リソースを絞り込み、その後にログフィルタで詳細を抽出する方が高速に動作します。

## 通常モードでのフィルタリング

### タイムラインのフィルタ

#### 正規表現によるタイムラインの絞り込み

「Add filter」ボタンを押すと、タイムラインを追加するためのダイアログが開きます。多くの場合は正規表現で名前を絞り込む方法が手軽で便利です。

![正規表現によるタイムラインフィルタ](/docs/ja/images/filter-regex-pattern.png)

| 番号 | 要素名 | 説明 |
| :--- | :--- | :--- |
| **1** | **正規表現パターン入力欄** | タイムライン名にマッチさせる正規表現パターンを入力します。 |
| **2** | **Include / Exclude 切り替え** | マッチしたタイムラインを含める（Include）か、除外する（Exclude）かを切り替えます。 |

タイムラインタイプを指定しない場合、すべての種類のタイムラインを対象として名前にマッチする正規表現でフィルタリングされます。

例えば、単に `pod` と入力すると以下のような要素にマッチします。

- すべての名前空間のすべての Pod（どの Pod も `pod` kind タイムラインタイプの子孫要素であるため）
- 名前に `pod` が含まれているその他のリソース
- すべての名前空間のすべての PodDisruptionBudget（`PodDisruptionBudget` kind タイムラインの `Pod` 部分にマッチするため）

階層ツリーの位置に関わらず名前でマッチするため、関連リソースをまとめて素早く絞り込むことができます。
例えば、`app-deployment` という Deployment、`app-deployment-abcde` という ReplicaSet、`app-deployment-abcde-fghij` という Pod が存在する場合：

- `app-deployment` と入力：Deployment、ReplicaSet、Pod のすべてがヒット
- `app-deployment-abcde` と入力：ReplicaSet と Pod のみがヒット

#### タイムラインタイプを指定した絞り込み

特定のタイプ（Kind や Namespace など）に限定して厳密にタイムラインを絞り込みたい場合は、タイムラインタイプを指定します。

![タイムラインタイプの選択](/docs/ja/images/filter-type-dropdown.png)

Timeline Type 入力欄をクリックすると、利用可能なタイムラインタイプの一覧が表示されます。各項目の横に表示されている数値は、データ内に存在するユニークな値の件数です。

タイムラインタイプを選択した状態では、正規表現による入力に加えて、一覧からチェックして選択する「Selection」モードも利用できます。

![選択式フィルタ](/docs/ja/images/filter-type-selection.png)

### ログのフィルタ

タイムラインの絞り込みに加え、ログの最低重大度（Min Severity）や検索キーワードを指定してログを絞り込むことができます。重大度以上のログが存在しないタイムラインは自動的にタイムライン上でも非表示になります。

ログの検索キーワード入力欄でも正規表現を使用できます。構造化ログの全フィールドおよび KHI が生成した 1 行サマリーのいずれかにマッチするログが検索・抽出されます。

## フィルタリングパイプライン（アドバンスド）

> [!NOTE]
> アドバンスドフィルタモードは試験段階の機能です。構文や仕様は将来変更される可能性があります。

KHI のアドバンスドモードでは、以下の 6 つのステップからなるパイプラインを通じてタイムラインとログが評価されます。

1. **ポジティブフィルタによるタイムラインの抽出**: 指定した CEL 式に合致するタイムラインを抽出します。
2. **子孫タイムラインの追加**: 抽出されたタイムライン配下にあるすべての子孫要素（サブリソースやコンテナなど）を追加します。
3. **ネガティブフィルタによるタイムラインの除外**: 指定した CEL 式に合致するタイムラインを除外します。
4. **ログフィルタの適用**: 残ったタイムライン内の各ログに対して CEL 式を評価し、マッチしないログを除外します。
5. **祖先タイムラインの追加**: ログが残っているタイムラインのためにツリー構造を維持して表示できるよう、親・祖先タイムラインを自動的に追加します。
6. **空のタイムラインの除外**: 有効なログが 1 件も存在しないタイムラインを最終表示から除外します。

通常モードのフィルタリングも、内部的にはアドバンスドモードの CEL 式フィルタに変換されて実行されます。

アドバンスドモードでは、タイムラインのリビジョンに含まれる特定フィールドにマッチする条件を指定したり、特定のログフィールドを直接評価する柔軟なフィルタリングが可能です。利用可能なフィールドや詳細な構文については、ツールバーの CEL 式ヘルプボタンをクリックしてご確認ください。
